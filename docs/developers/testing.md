# Testing

```sh
cd backend
uv run pytest
uvx ruff check app agent tests
```

The suite runs against a fresh database in a temporary folder and needs no network: AWS is simulated with `moto`, and webhooks are stubbed.
Any warning fails the suite.
A collector started by a test reports to a closed port, never to a server that happens to run on this machine, and stopping it waits for the process to exit.

The upgrade tests in `tests/test_migrate.py` run twice, on SQLite and on Postgres.
Postgres comes from the `pgserver` test dependency, which ships its own binaries and starts a throwaway server on a private socket, so nothing needs installing and parallel runs do not share a port.
Set `WH_TEST_POSTGRES_URL` to a SQLAlchemy URL to use a running server instead.

## What it covers

- Sign-in, two-step codes, roles and read-only support sessions.
- Rotating the session signing key ends every session, and a generated key file is readable only by its owner.
- No access-key id or private key sits in product config. The scan is proved on a planted key in each kind of config file it reads.
- An upgraded database puts existing rows in one project named Main, and a new company starts with that empty project. Afterwards its uniqueness rules, required columns and indexes match a fresh database.
- The permission matrix: the code is checked against a copy of the spec 0A table (8 roles by 20 permissions, 160 pairs), every role is called against a real route for each permission that has one, a member of one project cannot read, list or change another project's incidents, signals, fixes, WhiteHats, clones or findings, nobody reaches another company, and the last account owner cannot be removed.
  The route scan walks every route the app serves (`app.routes`, into each included router, plus the routes `main.py` adds itself): each uses `allow(...)` or is a listed public route.
  The shared account for these tests is `tests/matrix_account.py`: import `matrix_fixture` and ask for `matrix`.
- Project reads (`tests/test_project_isolation.py`): the board report, the briefing and its cache, Ask Big Hat and its suggestions and history, the Overview posture, the WhiteHats summary and the network summary each answer with one project's rows; raw logs and collector feeds are refused to project roles; Fix Factory answers only in Main and a run another project started is not Main's.
- Role rules (`tests/test_role_rules.py`, R-041): two different Approvers for a critical fix when the project asks, no self-granted project role, grants and removals with an audited reason, only an Account owner makes an Account owner, archived projects read-only for account roles and closed to project roles and new data, and account-wide settings refused to project roles. The browser side is `e2e/tests/role-rules.spec.js`.
- Audit and support by project: an action inside a project is filed under it and an account-level action is not; a Project admin reads only their project's trail; the owner and the auditor read every project's; a support session limited to one project is refused in another and on the account's shared pages, stays read-only inside it, and ends when the grant expires.
- Coming soon (PT.1): only AWS, CloudWatch and GitHub can be saved, synced or read; every other connector says Coming soon on the screen and in the API, is refused with 409, and is never read in the background; a project lists only the connections that can feed it; every main menu entry opens a working screen.
- The change trigger (`tests/test_changes.py`, VS.1): a pushed commit is kept once however often it is reported; a burst on one branch is one change; a pull request names its number and a closed or labelled one adds nothing; a repository no project holds is not read; only the files the diff touches are read, a deleted or unsafe or oversized file is not, and the skip is recorded; the diff starts at the last commit judged and falls back when GitHub has lost it; the newest of several waiting commits is judged and covers the older; a failed read is retried three times, an engine failure is "incomplete" never "clean", and a crashed run is taken up again; a signed push is judged after the answer and a redelivery or forged one changes nothing. `tests/prove_changes.py` is the live read-only proof against the proving ground, and `tests/send_push.py` replays a push to a running server.
- Review 8 fixes (R-046): an odd webhook signature header is a 401, not a 500; GitHub App secrets never reach a log, a response or an error; replayed GitHub calls must carry the API version and a Bearer token; three CloudWatch events in one millisecond are each read once across resumed reads; the server refuses the clone edges the Studio refuses; the Fix Factory run list leaves out other projects' runs; Main cannot be archived; each project gets its own daily score; a shared open finding counts once.
- The demo account (`tests/test_demo_projects.py`, AP.7): Acme (demo) has four projects, Fintech shop (the home project, slug `main`), Health platform, SaaS with AI and Whole estate. Each demo person opens exactly the projects and holds exactly the actions of spec 0A. The health engineer, the auditor and the Fintech shop Approver are refused what they may not do. Whole estate holds every open finding of the three, so the account count equals its count and each project card counts open findings the same way. A demo seeded before AP.7 is reshaped once at startup.
- Connections and projects: a scope narrows by every filter it names; one AWS connection attached to two projects with different tags puts each discovered resource only in its project; a push to a repository attached to two projects is a finding in both and one for the account; detaching stops new findings in that project and keeps the old ones; a log batch runs only the WhiteHats of projects in scope; an identity connection is account-wide and cannot be attached.
- Changing someone's role moves their account role and project memberships with it. The account export includes projects, members and the clone tables. Posture history reads one project.
- The operator journey: create a company, contract checks, waivers, invitation limited to the company domain, the admin joining with two-step sign-in, go-live blocked until ready, suspend and resume, offboard with export, delete with a certificate.
- Isolation: one company cannot read another's incidents.
- AI policy enforcement in the model gateway.
- Alerts channel test delivery.
- CloudWatch sync with cursors, feeding the log analyzer and the Cloud Posture WhiteHat. CloudWatch assumes a role. A stored access key is refused.
- WhiteHats: the catalog, planned entries refused, Identity, Endpoint and Cloud Posture signals. Sample signal titles and Fix Factory evidence both use `app/whitehats/signals.py`, so a cited WhiteHat has to be one that ships and the line has to be a title it raises.
- Every ATT&CK technique a WhiteHat tags a signal with is one MITRE still publishes (checked against the node library's ATT&CK list).
- The time stamps and offsets the Insider WhiteHat reads, each with lines it must read and lines it must not. Setup and the operator console refuse an offset more than 14 hours from UTC, and an impossible offset saved earlier is read as UTC instead of stopping log intake.
- A WhiteHat with no real delivery is waiting and counts as a blind spot, and that count matches the posture blind-spot count.
- Log shape mining, budgets and digests; network findings opening and resolving; a real local collector process.
- Retention removing old raw lines; help pages served safely.
- Connectors: every connector on the framework runs through the contract tests against recorded answers: sign-in and one probe per permission, a refused sign-in in plain words, every page read then nothing twice, a sample that keeps the bookmark, throttling waited out, discovery as a clone whose every node and edge the node library resolves, and pushed events refused by polled sources. Recordings live in `tests/recordings/connectors/`.
- Fix Factory split fixes (`tests/test_factory_pull_requests.py`, P8.3): from recorded runs of the pull request line, a fix says only that it was sent until pull requests exist, then lists them in merge order, says CI passed only when every pull request passed, becomes verified once all are merged, and failed with the reason when CI failed. Deciding a fix that belongs to an incident writes the timeline (`tests/test_fix_decisions_on_incidents.py`).
- Fix Factory: an approved code fix becomes verified or failed from a recorded run; a crafted run id never reaches the engine; a hung engine is asked once, for at most 2 seconds, by the Overview and by every screen that shows fixes, and its last known status shows for 30 seconds.
- A recorded Terraform state becomes clone nodes, groups and edges. Reading it again is an empty change set. Secrets in that state are not copied.
- Sense points: a hand-made graph ranks the node that covers the most remaining attack paths per unit of cost. Path weight counts each ATT&CK technique once and each missing control. The same graph ranks the same way twice. A watched node is not suggested.
- Projects: an empty project, one from a template and one from a connection scope; the home lists score, findings and connection health; a new project's overview does not list Main's incidents; a viewer added to one project cannot approve there and cannot open a project they were not given. The account home shows a score weighted by criticality, names the lowest project, and counts a finding on a shared resource once. The board report can be for one project or for the account.
- Decisions API v0: a run is clean or suspect, with rule id, evidence span, CWE and score, and the package does not call a model. House rules pass their own must-match and must-not-match examples. A boundary test fails if a rule names a scenario id, a scenario file name, or a string that exists only in a scenario patch. Engine JSON is normalised from recorded fixtures, and the secret text in that JSON is not copied onto the suspect.

## Browser tests

From the repository root, after the web app has been built (`cd platform/frontend && npm run build`):

```sh
cd platform/e2e && npm install && npx playwright install chromium && npx playwright test
```

The suite starts the platform itself, on a temporary database, and signs in with the seeded demo accounts. The web app's fonts ship with it, so no test reaches the internet, and every screenshot waits until they have loaded. Screenshots land in `platform/e2e/screenshots/`. The gate test checks Overview, Approvals and Fix Factory at 390, 768, 1024, 1440 and 1920 px, runs an axe scan, and fails on a console error or a failed API request. Its snapshots mask dates written as `<time>` and posture charts, which follow the day of the run, so a baseline stays valid the next day. Render a new absolute date on a gated screen as `<time dateTime=...>`. Tests that add collectors or other rows remove them when they finish, because every test in a run shares one database. One path through those three screens uses the keyboard only. A decisions test moves an incident one status at a time, with a note and undo, and confirms a role change before it is saved. A dispatched fix also blocks resolve. A failed fix does not: the dialog warns, the incident resolves, and the timeline records that the automated fix failed (R-045). A Fix Factory test plays back a real recorded run through a stand-in engine: the approved code fix blocks resolve until the run is approved and merged on the Fix Factory screen, then shows verified, and the incident resolves by keyboard. Ask Big Hat fills the window at 1440 and 390 px, and after several questions only its message list scrolls, ending on the newest answer. Undo matches the user id, runs once, and lasts the same 10 seconds as the toast. Changing your own role is refused. Working hours are saved by an Engineer, and screens hide or explain controls the person may not use. Incident, collector, company, and notable-shape rows each hold a real link in the main cell. Tab and Enter open the first incident. A modified click opens it in a new tab. A right-click on the row does not. An overview test checks that the briefing, the Approvals badge and the Approvals header all name the full decision count. The list shows the first 8, and says "and N more" when there are more. A labels test checks that the log analyzer's token budget has a visible name and hint, and that its empty state offers Deploy a collector. A sample-origin test checks that seeded rows wear a Sample tag and that the banner appears only while sample rows exist. The company name is not enough. Milestones and the agreement wear the tag when the seed wrote them. The network sample is a high finding that WhiteHat can raise. Approvals shows "Impact not simulated yet" until a linked Fix Factory run has real checks, and a manual approval says "Manual: carry this out in" the destination. The WhiteHats screen says "Not measured yet" and lists planned WhiteHats in their own section. The agents API returns no coverage number until one is computed. Setup can save a time zone and working hours, and refuses an unknown zone or a start that equals the end. Connectors say "Not connected", "Credentials checked, not reading yet", "Reading data", or "Not built yet". CrowdStrike and Jira cannot be saved. An incidents test opens one by hand from chosen signals, and the empty state says incidents are opened by hand for now. A split-fix test (`e2e/tests/split-fix.spec.js`) presses Apply Fix by keyboard, plays back the recorded pull request line through a stand-in engine (`e2e/recorded-split-factory.js`), and checks the three pull requests in order with CI on each, that nothing claims a pull request before one exists, that the merge note shows only while merges are awaited, and that a run whose CI failed is shown as failed. A replayed Fix Factory run is labelled "Recorded run, replayed" on the run, its timeline and its result. Ask Big Hat suggestions come from open incidents, pending decisions and WhiteHats that are waiting or not watching. The briefing and the offline answer name the WhiteHats that are waiting for data. With no incidents, none of them mention an incident. The offline answer says no model is connected and lists the facts on record. A sample-story test checks that every seeded signal linked to an incident uses a title a shipped WhiteHat can raise and shares a subject word with that incident. The browser opens the three open sample incidents and checks that each page stays on that one event. Opening Overview twice writes no posture snapshot. One company failing a snapshot does not stop the others. The posture chart draws a point for each measured day and leaves a gap where a day has none. The background loop is driven across a day change and records one snapshot per company. A sign-in line with no readable time is counted on the Insider Threat card. A Studio test imports the proving-ground clone as an engineer, checks the five areas, the library search, selection by mouse and keyboard, the problems list and the Draft state, refuses a file that is not JSON and a clone that names another company's vault, measures that no text on the canvas is under 11 px at the opening view, the overview and close up, and checks the narrow layouts: the library slides over at 768 px, the inspector is a bottom sheet, and a phone says the Studio is view only. Someone who cannot edit the canvas sees no Import button. A project test creates an empty project, one from the health template and one from a connection scope, switches between them, invites a viewer, and checks that Approve is disabled with the reason. With those three projects on the account home it records the weighted score and the lowest project. The account home, project settings and account settings pass the gate at all five widths. A demo-access test (`e2e/tests/demo-access.spec.js`) signs in as each of the seven demo people, checks the projects on the account home and in the switcher, the actions the server grants in each project and the Approve control or its reason, and writes the table to `screenshots/AP.7/demo-access.md`. It checks the Whole estate count, the sample banner and tags, the people list's access column, and walks the health engineer's path by keyboard only.

## Clone Studio library

From the repository root:

```sh
cd library && uv run pytest && uvx ruff check library tests && uv run python -m library.validate
```

The library tests resolve every node and group of the two templates and the proving-ground example to a real, non-Generic type, check property values and edge directions, and hold every type to the validator's rules: the file name, ATT&CK ids that MITRE publishes and has not retired, a deploy guide with all five sections, and one Generic type per family.

## Before a release

1. All tests pass and lint is clean.
2. Start with `./start.sh` and walk the operator journey in a browser: create a company, invite, accept in a private window, go live.
3. Deploy one collector of each kind and confirm they show *online*.

## Imports (PG.3)

`tests/test_changesets.py` covers the comparison and apply rules with no database. `tests/test_imports_api.py` drives the routes, including an import of what a fake AWS account (moto) found. `e2e/tests/import-review.spec.js` is the review journey in a real browser, with snapshots at the five widths. `scripts/check_state_import.py` checks a real state file and is not part of the suite (see [Importing an estate](importing.md)).

## The proving ground by hand, and 500 nodes (P2.5)

`e2e/tests/proving-ground-by-hand.spec.js` draws the proving-ground estate in the Studio the way a person does, inside the Fintech shop project, on its own server and database, and records a video (Playwright keeps it under `test-results/`).
It lists the clones already in the project first, makes a new one with a name of its own, drags every type from the library with real pointer events, fills the side panel (name, owner, notes, required properties) and draws the connections (the first four with the pointer, the rest from the side panel's *Draw a connection*).
It then checks every node and container is Described and has an owner and notes, reloads, takes screenshots at the five widths (`screenshots/P2.5/hand-built-*.png`), exports the clone and runs `e2e/check_clone.py` on the file (the clone schema, the secret and vault rules, the node library, and the Described count).
What is drawn is the plan in `e2e/proving-ground-plan.js`, written from the repository and not from the Terraform state.
`PLAN_ONLY=<n>` draws only the first n nodes while the plan is being changed.

`e2e/tests/canvas-500.spec.js` makes a generated 500-node clone (`e2e/estate-500.js`: 10 networks in one account, 690 connections) through the API, opens it, and records the page with Chrome's tracing while it fits, pans, zooms by wheel and by button, and lays out again.
A frame is the gap between two animation frames; the test fails when the longest is 100 ms or more, and writes `screenshots/P2.5/trace-summary.json` with the longest frame, the browser's own long-task report and the longest main-thread task from the trace, per phase.
Panning uses the middle button, because a drag with the main button that starts on a node moves the node.
`PERF_SOAK_MINUTES=5` also runs the memory check: it edits the 500-node clone (a nudge and its undo, a pan, a zoom) for that long and reads the heap after a forced collection (`screenshots/P2.5/heap-summary.json`).

`e2e/tests/studio-unset-choice.spec.js` guards a bug the hand-build found: a choice that was not made yet on one item (for example a function's Platform) showed the choice made on the previous item of the same type and was never saved, so the second function stayed Draft while the panel said it was filled.

`e2e/tests/proving-ground-compare.spec.js` is the comparison half of PG.3 and runs only when `PG_STATE_FILE` names the real state (git-ignored, it holds secret values).
It imports the exported hand-built clone, imports the state through the import screen into a new clone on a local server with no cloud access, accepts everything that has a library type, and exports both clones to `e2e/test-results/pg3-compare/`.
`uv run python ../e2e/compare_clones.py <hand> <imported>` (from `platform/backend`) prints the counts by provenance and the differences.

The browser tests never reach GitHub: `e2e/fake-github.js` replays the recorded answers of the real proving-ground repository (`GITHUB_API_URL` points the app at it).
`tests/proving-ground-compare.spec.js` also scans the repository; with `PG_LIVE_GITHUB=1`, `PG_GITHUB_INSTALLATION_ID`, `GITHUB_APP_ID` and `GITHUB_APP_PRIVATE_KEY_PATH` set it reads the real repository through the real App instead, read only.
The installation id changes when the App is reinstalled: read it from the App's own list (`tests/connector_kit.py: app_installation`), as `record_github.py --scan` and `prove_github.py --scan` do.
